# First actual hidden-mode result — 2026-10-23

## User observation

The affected user reported that the screen was still flickering if the tool was running. Immediately afterward, the experiment process was confirmed active in Hidden mode. This trial **did not eliminate the reported flicker**; no clear subjective improvement was reported. A degree of improvement was not quantitatively assessed.

The original browser animation had previously been reported comfortable while actually visible and ineffective when covered. That earlier browser observation must not be attributed to this new executable's visible mode, which has not received a separate user comparison.

## Concurrent software evidence

- Executable version 0.1.0, SHA256 `6C173604D62200A7866E42A61426AFB1A5C27C75CAFE82D11F2E3AC5A0B8E9CC`.
- Host: x64 .NET Framework process on an ARM64 Windows machine; matching x64 WebView2 loader. This was not a native ARM64 host test.
- Installed WebView2 runtime: 156.0.4314.42.
- Requested mode Hidden; actual top-level host HWND visibility false.
- WebView2 controller requested visibility true; document visibility reported visible.
- Normal animation mode, noPaint=false; page running=true. This was not the self-test's no-paint mode.
- Four recent samples approximately 59.28–60.37 JavaScript rAF callbacks per second. The page had accumulated approximately 5,014 callbacks over 83 seconds at the readback.
- These are execution/visibility observations, **not** a physical scanout, DWM presentation or luminance measurement.

The affected user's observation was made after the assistant stopped interacting with the computer; the software readback was taken after the user reported the result. Disabling the original browser animation was requested, but its final checkbox state was not instrumentally verified. Current brightness, DRR, G-SYNC and refresh-rate state were not recaptured during this particular hands-off trial; refer to the separate baseline observations rather than assuming they were unchanged.

The experiment was stopped after the report. No driver, registry, ICC or global browser setting was changed by this trial. Local process identifiers and raw logs are intentionally omitted from this public note.

## Interpretation limits

An active hidden JavaScript animation was insufficient to eliminate the reported symptom in this implementation and trial. This does not prove a hardware defect, a particular PSR/Panel Replay fault, that all hidden rendering approaches fail, or that the new visible mode is equivalent to the original browser baseline. Callback activity alone is not an effective workaround criterion.

The normal tool also polls diagnostic state once per second, and the host uses x64 compatibility execution. Those are part of this experiment's workload. The result does not isolate each of those factors independently.
